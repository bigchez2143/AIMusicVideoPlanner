# Contributing

Start with an issue describing the user workflow you want to improve. Small pull requests are easier to review. Run the core tests and the JavaScript syntax check, then check the interface in a browser.

Core priorities are reliable saving, precise lyric and scene timing, notes that are never silently overwritten, readable complete exports, and a useful local assistant connection.

Do not commit real songs, character references, project databases, model weights, tokens or local environments. Use synthetic test fixtures. Preserve unknown project fields and stable IDs when changing the schema.

Useful next steps include broader platform testing, durable transcription job recovery, streaming exports for large media packages, a packaged Windows executable, explicit provider adapters with model/credit approval, and a final video render pipeline. Provider integrations must not silently substitute models or submit paid jobs.

Report a security issue privately to the repository owner instead of including credentials or private project content in a public issue.
